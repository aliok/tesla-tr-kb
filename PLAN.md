# Tesla TR Knowledge Base - Implementation Plan

## Context

Build a mobile-first knowledge base website for Tesla owners/enthusiasts in Turkey. The site will be shared in Telegram groups to answer frequently asked questions via direct links. Each question has a unique anchor URL so users can share specific Q&A pairs.

## Architecture

**Tech stack**: HTML, CSS, TypeScript (frontend), jQuery (via CDN), Node.js scripts (build tools), GitHub Actions (CI), Netlify (hosting).

**Key design decisions**:
- Use native `<details>/<summary>` HTML elements for accordion — works without JS, semantic, accessible
- TypeScript handles deep-linking (open accordion + scroll on hash navigation)
- TOC is auto-generated by a Node.js script that parses the page HTML files
- No bundler — just `tsc` for TypeScript compilation and file copying via shell commands

### 4. `tsconfig.json`

### 5. `netlify.toml`
- Build command: `npm run build`
- Publish directory: `dist`
- Node version from `.nvmrc`

### 6. `src/index.html` — Landing page
- Title, brief description of the KB
- TOC section between `<!-- TOC_START -->` and `<!-- TOC_END -->` markers
- The generate-toc script will fill this section with links grouped by category
- Includes jQuery (CDN) and compiled `app.js`

### 7. `src/styles.css` — Mobile-first styles
- System font stack (fast loading)
- Mobile-first responsive layout (max-width media queries for larger screens)
- `<details>/<summary>` styling: custom arrow, padding, borders
- Highlight animation for deep-linked items (brief flash on scroll-to)
- Clean, readable typography optimized for mobile
- Simple nav header with back-to-home link on category pages

### 8. `src/app.ts` — Frontend logic
- On `DOMContentLoaded`:
  1. Check `window.location.hash`
  2. If hash matches a `<details>` id, set its `open` attribute and scroll into view
  3. Add brief highlight class for visual feedback
- On `<summary>` click: update `window.location.hash` to the parent `<details>` id
- On `hashchange` event: handle in-page navigation
- Uses jQuery as specified

### 9. `src/pages/genel.html` — Example category page
- Same header/nav structure as index
- Contains several example `<details>` accordion items with Turkish content
- Each `<details>` has a unique `id` (kebab-case Turkish, e.g., `neden-tesla`)
- Structure per item:
  ```html
  <details id="neden-tesla">
      <summary>Neden Tesla?</summary>
      <div class="answer">
          <p>Answer content here...</p>
      </div>
  </details>
  ```

### 10. `scripts/generate-toc.js`
- Reads all `.html` files from `dist/pages/`
- Uses regex to extract:
  - Page title from `<h2>` element
  - Each `<details id="..."><summary>...</summary>` pair
- Generates TOC HTML: sections per category, each with a list of question links
- Link format: `pages/genel.html#neden-tesla`
- Reads `dist/index.html`, replaces content between TOC markers, writes back

### 11. `.github/workflows/ci.yml`
- Triggers on push to `main` and pull requests
- Uses `actions/setup-node@v4` with `node-version-file: '.nvmrc'`
- Steps: checkout → setup node → `npm ci` → `npm run build`
- Validates the build succeeds (no deployment — Netlify handles that)

### 12. `AGENTS.md`

Detailed contributor guide with the following sections:

#### Project Overview
- What the project is, who it's for, how it's used (Telegram link sharing)

#### Dev Environment Setup
- Install nvm, use `.nvmrc`, `npm install`, `npm run build`, `npx serve dist`

#### Content Authoring Rules

**Anchor/ID naming conventions:**
- All IDs must be kebab-case, lowercase, ASCII-only (no Turkish special chars in IDs)
- Turkish chars mapping: ç→c, ğ→g, ı→i, ö→o, ş→s, ü→u
- IDs should be short but descriptive, max ~40 chars
- Prefix with a verb or keyword that captures the question topic
- Examples: `neden-tesla`, `sarj-suresi-ne-kadar`, `garanti-kapsami`
- IDs must be unique across the entire page (not just within a section)
- Once published, **never change an ID** — people share these URLs in Telegram

**Adding a new category page:**
- Create a new `.html` file in `src/pages/`
- Filename should be lowercase kebab-case Turkish (e.g., `satin-alma.html`, `sarj.html`)
- Copy the structure from `genel.html` as a template
- Update the `<h2>` title — this becomes the category name in the TOC
- The page will be automatically picked up by `generate-toc.js`

**Adding a new question to an existing page:**
- Add a new `<details>` block with a unique `id` and a `<summary>` containing the question
- Place it in logical order within the page
- Keep answers concise and factual
- Use `<p>`, `<ul>`, `<a>` tags inside `.answer` div — no complex HTML
- Always wrap answer content in `<div class="answer">`

**Content formatting rules:**
- Questions in `<summary>` should be written as natural Turkish questions (with `?`)
- Answers should be plain, helpful text — no marketing language
- External links should use `target="_blank" rel="noopener noreferrer"`
- Keep each answer self-contained (don't reference other answers by "see above")

**Page ordering:**
- The TOC generator sorts pages alphabetically by filename
- To control ordering, prefix filenames with numbers: `01-genel.html`, `02-satin-alma.html`, etc.
- Or keep alphabetical and accept that order

#### HTML Structure Conventions
- Document the exact `<details>/<summary>` structure expected
- Show the full page template with header, nav, main, scripts

#### How TOC Generation Works
- Explain that `scripts/generate-toc.js` runs during build
- It reads `dist/pages/*.html`, extracts `<h2>` titles and `<details>` items
- It replaces content between `<!-- TOC_START -->` and `<!-- TOC_END -->` in `dist/index.html`
- Contributors should never manually edit the TOC section in `index.html`

#### CI/CD
- GitHub Actions runs `npm run build` on every push/PR to validate
- Netlify auto-deploys from `main` branch
- Build must pass before merging PRs

## Build Flow

```
npm run build
  1. clean      → rm -rf dist
  2. copy       → mkdir -p dist/pages && cp HTML/CSS files to dist/
  3. compile    → tsc (src/app.ts → dist/app.js)
  4. generate-toc → node scripts/generate-toc.js (fills TOC in dist/index.html)
```
